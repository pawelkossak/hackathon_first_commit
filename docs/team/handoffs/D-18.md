# D-18: `fraudRevealed` engine event, `lapStart` after rewind to week 1

## Built
- **New engine event `fraudRevealed`.** It is in the `EngineEvent` union (`engine/types.ts`) and in `EngineEventTypeSchema` (`engine/schema.ts`). The `EngineEventTypesInSync` guard is green. The payload:
  ```ts
  { type: "fraudRevealed"; week: WeekNumber; eventId: EventId; ledgerId: LedgerId; amount: Pln; date: IsoDate }
  ```
  In the demo lap it is `{ type: "fraudRevealed", week: 5, eventId: "E1", ledgerId: "L08", amount: -35700, date: "2026-12-23" }`.
  - `amount` is the signed amount of the booked ledger row: an outflow, so it is below 0, the same as `Transaction.amount`. Show it as 35 700 zł.
  - `date` is the reveal date, taken from the `reveal` effect in `level1.json`.
  - No value is a literal in the code: all of them come from the data and the settled forecast.
- **`data/reactions.json`** maps `fraudRevealed` to `exasperated` with the prefix `rx.fraud`. The schema and the cross-check (`checkReferences`: every event type has a mapping) accept it.
- **Emission** happens in `settleWeek` (`engine/turn.ts`, `fraudSignals`). The signal goes into the `resolveWeek` result `events` and into `state.emitted`. All of these must hold:
  - a resolved choice carries a `reveal` effect (only E1 `pay_as_is` does);
  - the week being settled contains the reveal date (23 XII, which is T5);
  - the lap did not crash before the reveal date;
  - the true ledger paid the row to the changed account (L08 with `eventId: "E1"`) on or before the reveal date.

  It is never emitted on the `check` path. A replay emits it again only when the replay settles the reveal week: a rewind to T1–T5 does, a rewind to T6 or T7 does not.
- **Order of the signals in one week resolution:**
  1. `fraudRevealed`;
  2. then `crash`, `lapWon` or `quietWeek`;
  3. then the signal of the next week's shown event (`bigProject`, `loanOffered`, `lateClient`).
- **`rewind(state, 1)`** emits `[{ type: "lapStart", week: 1 }]` first, then the restored week-1 event signals. In the demo deck there are none, because E1 has no signal. This works from every status. A rewind to weeks 2–7 never emits `lapStart`.

## Proof
- `engine/events.test.ts`, "D-18 fraudRevealed":
  - the data matches the spec: reveal on 23 XII, which falls in T5, and the row is L08;
  - with C1 the event fires exactly once, in the T5 resolution, and the lap still crashes on 8 I (ET-E02);
  - with no card the lap crashes on 22 XII (ET-E01) and nothing is emitted;
  - on the check path nothing is emitted, whether no card, C1 or C6 is played;
  - with C3 nothing is emitted;
  - replay after a rewind to weeks 2–5 emits it again, a rewind to week 6 does not, and a rewind to week 1 followed by `check` does not.
- `engine/turn.test.ts`: "D-18 rewind to week 1 emits lapStart from every status". The existing rewind-signal test now expects `lapStart` for week 1.
- `engine/schema.test.ts`:
  - reactions.json maps every engine event type exactly once, and `fraudRevealed` maps to `exasperated` with `rx.fraud`;
  - a missing mapping fails the cross-check.
- `pnpm check` is green: typecheck, lint, 102 tests, build.

## API changes
No function signatures changed. The changes are additive:
- `EngineEvent` gains `fraudRevealed`, and `EngineEventType` / `EngineEventTypeSchema` gain `"fraudRevealed"`. Any exhaustive `switch` over `EngineEvent["type"]` in the ui or narrative lanes must add a case.

Behaviour changes:
- `rewind(state, 1).emitted` was `[]` and is now `[lapStart]`.
- The T5 `resolveWeek` on the E1 `pay_as_is` path, when the lap survives 22 XII, now carries `fraudRevealed`.

## For the narrative lane
- Add the `rx.fraud.*` lines. The emotion is `exasperated`; the copy is the narrator's reaction to the reported fraud.
- Numbers come only from the payload: `amount` (use the absolute value) and `date`, which passes the number guardrail.
- The cooldown is one reaction per week resolution. In the T5 resolution of the C1 + `pay_as_is` path, `fraudRevealed` is the first event and the next event, `lateClient` (E6 shown in T6), comes after it. Pick by the cooldown rule.
- After a rewind to T1, react to `lapStart` with `rx.welcome`.
