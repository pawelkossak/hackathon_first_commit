# E-11: level 2 „Pierwszy pracownik” engine

## Built
- **`data/level2.json`.** The synthetic scenario of FIRST-EMPLOYEE-SCENARIO.md:
  - 1–21 II 2027 and an opening balance of 8 000;
  - base ledger B1–B5;
  - three weeks with their two choices and a passive default (defer, wait, common);
  - choice effects (H-SALARY −6 000 on 10 II, H-EMPLOYER −1 200 on 15 II, A-ADVANCE +3 000 on 8 II with B2 set to 6 000, reserve 4 300 released by B5);
  - star rules and the storage key.
- **Validation.** `Level2FileSchema` and `EmployeeSaveSchema` in `engine/schema.ts`. The file is loaded and parsed in `engine/data.ts` as `gameData.level2`.
- **Cross-checks (`checkLevel2`).** These checks run on the data file:
  - week order, coverage of the period, and that each week's choices match its decision;
  - the advance conserves revenue: advance + reduced B2 = original B2;
  - employer costs = 20 % of the salary;
  - the reserve equals the tax row.
- **`engine/schema.test.ts`.** Now also covers `level2.json`: schema, spec table literals, and a broken-conservation case.
- **`engine/employee.ts`.** Pure functions; inputs are never mutated.
  - Rules: inflows before outflows on the same day; a crash when cash goes below 0 on a transaction; shortfall = −balance.
  - The reserve is an earmark only. Each day it holds `min(4 300, max(0, cash))` from week 3 start until 19 II, when B5 is paid. It creates no transaction.
- **New error codes (additive) in `engine/errors.ts`:** `choice_missing`, `invalid_save`.
- **Engine events.** None added. The module reuses existing event types:

| When | Event |
|---|---|
| create | `lapStart{week:1}` |
| a week settled without a crash | `quietWeek{week}` |
| crash | `crash{week, crash}` |
| completion | `lapWon{week:3, stars: []}` |

  `stars` stays empty because the level-1 `StarId` does not fit. Read the star count from `employeeScore`.

## Star rule (the spec is silent, simplest consistent rule)
| Outcome | Stars |
|---|---|
| Not completed | 0 |
| Completed | 2 |
| Completed, and the reserve held the full 4 300 at the end of 18 II (the day before the tax) | 3 |

Hiring is never required. The two spec paths give 3 and 2 stars.

## API (exported from `engine/index.ts`, additive; level-1 signatures unchanged)
```ts
EMPLOYEE_STORAGE_KEY: "pilot.employee.v1"
createEmployeeGame(): EmployeeState
employeeForecast(state: EmployeeState): EmployeeForecast
chooseEmployeeAction(state: EmployeeState, choiceId: EmployeeChoiceId): EmployeeState
resolveEmployeeWeek(state: EmployeeState): EmployeeWeekResolution
rewindEmployeeGame(state: EmployeeState, week: EmployeeWeek): EmployeeState
employeeScore(state: EmployeeState): EmployeeScore
restoreEmployeeGame(saved: unknown): EmployeeState
```

| Function | Behaviour | Errors |
|---|---|---|
| `chooseEmployeeAction` | Can replace a choice that is not settled yet. | `not_playing`, `invalid_choice` |
| `resolveEmployeeWeek` | Settles the current week. | `not_playing`, `choice_missing` |
| `rewindEmployeeGame` | Keeps the choices of earlier weeks and replays from data. | `invalid_week`, `no_snapshot` (week not reached) |
| `restoreEmployeeGame` | Reads only `schemaVersion`, `level`, `choices`, `weeksResolved` (must be 1…k). Recomputes everything else. | `invalid_save` |

Types are in `engine/types.ts`: `EmployeeState`, `EmployeeChoices`, `EmployeeForecast`, `EmployeePoint`, `EmployeeReserveView`, `EmployeeTransaction`, `EmployeeWeekResolution`, `EmployeeScore`, `EmployeeChoiceId`, `EmployeeWeek`, `Level2File`, `EmployeeSave`.

## State shape
```ts
EmployeeState {
  schemaVersion: 1; level: 2;
  week: 1 | 2 | 3;               // stays on the crash week, stays 3 after completion
  status: "playing" | "crashed" | "completed";
  choices: { hiring: "hire"|"defer"|null; invoice: "advance"|"wait"|null; tax: "reserve"|"common"|null };
  weeksResolved: (1|2|3)[];       // crash week included
  balance: Pln;                   // cash at the end of the last settled week (8 000 before week 1)
  reserved: Pln;
  booked: EmployeeTransaction[];  // on a crash: up to, excluding, the rejected transaction
  crash: Crash | null;            // {week, date, transactionId, shortfall}
  emitted: EngineEvent[];
}
```
Forecast points: `{date, week, openingBalance, balance, reserved, available, transactions, counterfactual}`. Undecided weeks use the passive default, listed in `assumedChoices`.

## Proof (`engine/employee.test.ts`, 13 cases; spec literals)
- **Cash gap and rewind:**
  - hire + wait crashes on 10 II with a 900 shortfall (`H-SALARY`);
  - rewind to week 2, then advance + reserve, completes with 1 500 and 3 stars.
- **Deferral:** defer + wait + common completes with 8 700 and 2 stars.
- **Advance conservation:** 3 000 + 6 000 = 9 000.
- **Hire effects:** −6 000 on 10 II and −1 200 on 15 II.
- **Tax:** paid once (only B5 on 19 II). The reserve is funded only up to cash: 2 800 on 15 II, then 4 300 from 17 II, released on 19 II.
- **Same-day order:** inflows before outflows.
- **Immutability:** deep-frozen inputs stay unchanged across every function.
- **Restore:** a save with tampered balances restores to the same state; a pending choice restores; a crashed save restores.
- **Guards:** 10 invalid saves give `invalid_save`. `invalid_choice`, `choice_missing`, `no_snapshot`, `invalid_week` and `not_playing` are covered.

## For the ui lane (U-18)
- **Remove the UI-side logic.** The U-18 handoff describes a `lib/ui/level2-store.ts` with its own `computeLevel2`. It is not on develop. Replace any such logic with these engine calls; the UI computes no numbers.
- **Flow:**
  1. `createEmployeeGame()`.
  2. Preview a choice with `employeeForecast(chooseEmployeeAction(s, id))`.
  3. `resolveEmployeeWeek(s)`.
  4. After a crash, `rewindEmployeeGame(s, 2)`.
  5. At the end, `employeeScore(s)`.
- **Persistence:**
  - Save the whole `EmployeeState` JSON under `EMPLOYEE_STORAGE_KEY`. On load, call `restoreEmployeeGame(JSON.parse(raw))` and handle a `RuleError` `invalid_save` by starting fresh.
  - The global reset clears the key.
  - Show save failures explicitly.
- **Lock:** use level 1 `core.level2Unlocked` (already in the engine).
- **Labels:** choice titles (dev only) and `textKey` per choice are in `gameData.level2.choices`.
