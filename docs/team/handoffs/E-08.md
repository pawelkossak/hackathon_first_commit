# E-08: agent rules — Klient A, Doradca banku, AI-CFO hint (D-17)

## Built
- `engine/agents.ts` (new) holds `negotiateWith`. `index.ts` `negotiate` only delegates to it.
  1. A lap that is not `playing` (`completed` or `crashed`) throws `RuleError("not_playing")`. This uses the existing code.
  2. The 4th message to the same agent in the same week returns `blocked: true` and `outcome: "blocked"`, with the agent's fallback line id (`a.fallback` / `bank.fallback`) and `numbers: []`. The state does not change. The count is per agent and resets each week (turn.ts, unchanged).
  3. Otherwise the **first matching rule** of `data/agents.json` decides. A rule matches on:
     - intent;
     - week window;
     - condition;
     - its card, if it has one: the card must be playable now (`disabledReason === null`) and not in `neverOffers`.

     When nothing matches, the agent's `unknown` rule applies, which shows quick replies.
  4. The outcomes `accept` and `inform_allow` play the card through **`applyCard`, the same path as `playCard`**, as the player's own decision: competence own 2, `goodMove`, the week's action used, `forecast.committedCards`, and the drilldown. Nothing is booked twice. The E-07 open point 2 is closed.
  5. `counter` sets `counterPending`. A played deal clears it, and it otherwise carries from T1 into T2.
  6. The rule's `relationsDelta` applies, clamped to 0…5 (rude −1).
  7. `negotiationOpen` is emitted on an agent's first message of the week. The applied card's events follow it.
- **`numbers`** (number guardrail) lists every number the reply may mention, all computed by the engine:
  - C1 (`counter` and `accept`): the counter percent 30, 15 000, day 3 (3 XII), cost 0.
  - C2: 2 (%), 19 889, 406, gross 20 295, and the day of this week's payout.
  - C4: limit 15 000, 150, the interest estimate (44 in T1), the total (194), and the rate 12 (%).
  - Refusals and fallbacks: `[]`.
- **D-17**: `safeCards` (cards.ts) returns only safe cards without a product when there is at least one. Otherwise it returns the safe products, cheapest first, with their engine cost. Two functions use it:
  - `getCfoHint`: options are `safeCards(...).slice(0, agents.cfo.optionCount)`.
  - **`delegateBestCard`**: the same product-last rule applies. GAME-DESIGN §2 "plays the cheapest valid action" does not say a product must win on price, and hard rule 3 forbids a product bias. So delegation picks the cheapest card without a product, and a product only as the last resort.
- `data.ts` load checks:
  - every agent has an `unknown` fallback rule (any week, no card);
  - a counter rule has `counterPercent` and `cardId`;
  - an accept or inform_allow rule has `cardId`;
  - `neverOffers` is respected (the check already existed).
- `data/agents.json`: the Klient A counter rule now has `cardId: "C1"`, the card it leads to. This way a counter is never offered when C1 cannot be played. The schema comment on `cardId` documents this.

## Interpretations (please review)
1. **No percent** in `ask_advance` gets the 30 % counter („client names her terms”). An invalid percent (≤ 0, not finite) is treated as no percent. Any p ≤ 30 is accepted as the C1 effect, which is the fixed 15 000 on 3 XII (spec: "accept: C1 effect").
2. **Deal card not playable** in these cases: week action used, C1 already played, INV-A1 not pending, C4 active. The rule does not match, so the agent answers `quick_replies` with the fallback line. NegotiationResult carries no reason. Adding one would be an interface change. The UI can show `getAvailableCards` reasons.
3. **Bank `inform_allow`** ("gap already closed, inform not needed, allow anyway"): C4 **is applied**, because the player asked explicitly and the bank has no separate confirm intent. If narrative wants a confirm step, it should ask the player first and only then send `ask_overdraft`.
4. The bank has no rule for the Klient A intents, so they get `bank.fallback`. The bank never applies C5 (`neverOffers: ["C5"]`, which is checked at load and in matching). C5 remains a non-bank SMS loan card only.

## API changes
No signature changes, no new types, no new error codes or events. Behaviour changes:
- `negotiate` applies the rules, and throws `not_playing` after the lap.
- `getCfoHint.options` and `delegateBestCard` offer a product only as the last resort (D-17). In T1 of the demo the hint is now C1, C2. Before, it was C1, C4.
