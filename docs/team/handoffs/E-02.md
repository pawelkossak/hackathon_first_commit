# E-02 — forecast: daily balance, same-day order, business days, crash detection

## Built
- `engine/forecast.ts` (new) replaces the fixture forecast. It builds the transactions in three steps: the ledger as written, then the overlays, then the business-day shift. After that it runs the days from 21 XI to 10 I.
  - Overlays are pure `ForecastOverlay` functions in `forecastOverlays`: `cardOverlay` first, then `eventOverlay`. E-03 and E-04 extend these two functions. The pipeline itself stays as it is.
  - **U-10**: on one date, inflows are booked before outflows (`sameDayOrder`). Otherwise the list keeps its order. Point transactions are listed in booking order.
  - **U-12**: `toBusinessDay` / `isBusinessDay` / `dayOfWeek` in `engine/calendar.ts` use the holidays from `level1.json`. The shift applies to every transaction date. With the current data it changes nothing, because the data already holds the shifted dates. The test checks that the rule reproduces every ledger `date` from its `dueDate`, and every C2 payout date from Tuesday + 3 days.
  - **Crash**: the first transaction after which the balance is below −`core.overdraftLimit`. Its shortfall is −limit − balance. Points after the crash date are marked `counterfactual`. With a crash, `low` and `endBalance` are null and `counterfactual` holds `{ low, endBalance }`.
  - Overdraft interest (only when a limit is set) and runway are unchanged from E-01.
- **Card money overlay.** ET-F04 and ET-F05 need it, so it is implemented for every card effect type, driven by `level1.json` (played week → payout or inflow date):
  - C1 inflow;
  - C2 and C6 remove L11 and add the payout;
  - C3 moves L08;
  - C5 adds the inflow and `C5-R` (20 I, outside the forecast range);
  - C4 adds no transaction, because its limit lives in core.

  E-03 still owns eligibility, windows, costs and the ET-C verification.
- **Event overlay: E6 only** (needed by ET-F02):
  - A resolved event applies its `move_invoice` effect when `core.invoiceState` still matches.
  - With `includeFutureEvents` (the default), a forced and still unresolved event of the seed deck applies its only choice as the scripted future.
  - `transaction` effects (E1 / E2 / E3) are not booked yet. That is E-04.
- `engine/types.ts`: added the compile-time guard `EngineEventTypesInSync`. It checks that `EngineEvent["type"]` equals `EngineEventType` (the QA P2 from E-01). I checked it by hand: adding a variant to only one list fails `tsc` with TS2344.
- `engine/fixture.ts` now keeps only the initial-state builders and `weekDates`. `index.ts` `forecast` calls `computeForecast`. `resolveWeek` now settles from the real forecast.

- `pnpm check` green (typecheck, lint, 29 tests, build).

## API changes
None. The `forecast(state, options?)` signature is unchanged. Additive changes only:
- the exported type `EngineEventTypesInSync`;
- the doc comment of `Forecast.runwayDays`, which now says it is based on the balance at the start of the current week, as the code already computed it.

## Open points
1. The card money overlay is already in place, so `previewCard().after` now differs from `before`. E-03 should check the ET-C values against it rather than add a second overlay.
2. Overdraft interest also sums counterfactual days after a crash. That only matters when a limit is set and the lap still crashes. E-03 should confirm this against ET-C08 / ET-C09.
3. `runwayDays` uses `core.balance` (start of the current week), not the balance at `from`.
