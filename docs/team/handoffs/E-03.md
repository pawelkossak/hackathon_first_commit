# E-03: action cards C1–C6

## Built
- `engine/cards.ts` (new) holds the card rules. The money effects stay in the E-02 forecast card overlay. I checked them against every ET-C value and found nothing to change.
  - `disabledReason(core, cardId)` checks in this order:
    1. `not_playing`
    2. `already_played`
    3. before the window: `outside_window`
    4. after the window: the named reason (`budget_closed` for C1 from T3, `bank_too_late` for C4 from T4), else the failing eligibility, else `outside_window`
    5. exclusivity and eligibility
    6. `week_action_used`
  - An open event never disables a card (contract: no event consumes the optional action).
  - Exclusivity C2 ↔ C6 comes from `exclusiveWith`. After C6 the reason is `invoice_financed` („Faktura już sfinansowana”). After C2 it is `invoice_paid` („Faktura już opłacona”).
  - `ledger_not_booked` (C3, C5): L08 counts as booked once its forecast date is before the start of the current week. So C5 is still playable in T5 and disabled from T6 with `payment_already_booked`.
  - `applyCard` handles the bookkeeping of a play:
    - the week's action, hand, played list and fixed cost;
    - Relacje, clamped to 0…5;
    - competence: own or delegated milestone, never lowered, none for products;
    - invoice state and overdraft limit.
  - `applyCard` emits `goodMove` when an own (not delegated) play removes the forecast crash.
  - `cardCost`: C4 is 150 plus the overdraft interest estimate (194 in the demo seed). Every other card has its fixed cost.
  - `safeCards`: playable cards with no crash after the play, cheapest first, ties broken by key.
- `engine/score.ts` (new) has `lapScore`. It applies at lap end in `resolveWeek`:
  - cost of money = fixed costs + overdraft interest;
  - stars from the `level1.json` star rules: Pilot is `pending` until the plan is saved and `missed` when the lowest balance < 0;
  - avoided cost and unlock.
  - On a crash every star is `missed`.
  - It is needed for the ET-C star and cost columns. E-06 still owns the ET-S verification.
- `engine/index.ts` changes:
  - `playCard` uses `applyCard`.
  - `getAvailableCards` and `previewCard` use `disabledReason` and `cardCost`.
  - `previewCard` of a playable C5 puts `{type:"loanOffered", via:"C5_preview"}` into `simulated.emitted`. This fixes the QA P2 from E-01 without a signature change. A disabled preview returns `simulated = state` with `emitted: []`.
  - `delegateBestCard` plays the cheapest safe card as delegated and throws `no_safe_card` when no card is safe.
  - `getCfoHint.options` returns the two cheapest safe cards while there is a risk. I did this early for E-08 because it uses the same helper.
- `engine/forecast.ts`: overdraft interest now counts only real days, through the crash date. It never counts counterfactual days (the E-02 open point). ET-C08 (44) and ET-C09 (39) have no crash, so they are the same either way.
- `engine/data.ts`: new load-time checks:
  - C6: fee = round(rate × gross), payout = gross − fee, cost = fee;
  - C2: payout = gross less the discount, cost = gross − payout.

## API changes
No signature changes. Behaviour changes:
- `CardView.cost` and `CardPreview.cost` for C4 now include the interest estimate (`costIsEstimate` stays true).
- `delegateBestCard` now plays only a safe card.
- `getCfoHint.options` is filled.
- At lap end, `core.costOfMoney` includes the overdraft interest, and `core.lowestBalance` is set.
