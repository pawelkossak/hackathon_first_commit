# E-01 — engine types, API surface with fixtures, data files with Zod

## Built
- `data/persona.json`, `data/level1.json`, `data/agents.json`, `data/future-script.json`, `data/reactions.json`, copied from ENGINE-DATA-AND-TESTS.md §1–§6 and SYNTHETIC-DATA.md §3–§4.
- **Paweł's earlier quiz model is gone.** The old `engine/types.ts` (Question/Answer) and `data/level1.json` (weeks/answers) were replaced completely by the specification model. Please tell Paweł.
- `engine/schema.ts`: Zod schemas for every data file. Data types are inferred from them.
- `engine/data.ts`: imports the JSON modules, runs `parse` when the module loads, then cross-reference checks (`checkReferences`). Bad data throws at import time.
- `engine/types.ts`: GameState / GameCore / AccountState, Forecast, CardView, CardPreview, CurrentEvent, WeekResolution, NegotiationResult, CfoHint, Plan, and the typed **EngineEvent** union of §6 (`lapStart`, `playerReturns`, `bigProject`, `negotiationOpen`, `lateClient`, `loanOffered`, `goodMove`, `crash`, `quietWeek`, `lapWon`, `planValidated`).
- `engine/errors.ts`: `RuleError` with a stable `code`, plus `isRuleError`.
- `engine/index.ts`: every function of RUNTIME-ENGINE-CONTRACT.md. These are fixture bodies built from data only (`engine/fixture.ts`) and `engine/calendar.ts` (UTC dates).

## API (final signatures, other lanes code against these)
```ts
createGame(seed?: string): GameState            // default "demo"
resetGame(seed?: string): GameState
forecast(state, options?: { includeFutureEvents?: boolean }): Forecast
getAvailableCards(state): CardView[]
previewCard(state, cardId): CardPreview          // { before, after, simulated, ... }
playCard(state, cardId, delegated?: boolean): GameState
getCurrentEvent(state): CurrentEvent | null
resolveEvent(state, choiceId, delegated?: boolean): GameState
resolveWeek(state): WeekResolution               // { state, week, transactions, endBalance, crash, events }
rewind(state, week): GameState
createPlan(state, cardId): Plan                  // draft, not saved
savePlan(state, cardId): GameState               // prospective state: persist it, then show success
advanceAccountClock(state, date?: IsoDate): GameState  // default 2026-12-05
negotiate(state, agent: "klient_a" | "bank", intent, percent?: number): NegotiationResult
getCfoHint(state): CfoHint
delegateBestCard(state): GameState
```
Also exported: all types, `RuleError`, `isRuleError`, `gameData` (validated data, e.g. week dates, markers, card titles), `DEMO_SEED`, `SCHEMA_VERSION`.
Engine events: every transition writes the events it emitted into `state.emitted`, which is replaced on each call. `resolveWeek` also returns them in `events`.

## What is a fixture (replaced by later tasks)
- `forecast`: ledger as written, inflows before outflows, crash below −limit. There are no card or event overlays and E6 is ignored (E-02/E-03/E-04). `includeFutureEvents` is accepted but has no effect yet.
- `playCard`: books cost, relations, competence, invoice state and overdraft limit, with no money effect in the forecast (E-03). Exclusivity, window and played reasons are already in place.
- `getCurrentEvent`: demo deck by week. The E5 `gap_open` condition is not checked yet (E-04).
- `resolveWeek`: settles from the fixture forecast. Simple stars and unlock at week 7 (E-05/E-06).
- `negotiate`: counts messages (max 3) and always answers `quick_replies` with the fallback line (E-08).
- `getCfoHint`: risk only, `options: []` (E-08). `delegateBestCard`: the cheapest playable card, not yet "safe" (E-08).
- `createPlan`: uses the C1 template from future-script.json. Other cards get a placeholder plan (E-09). `advanceAccountClock` moves the clock only, with no replay or matcher yet (E-09).

## Open points and spec questions
1. **L07 counterparty**: the spec says "ZUS/US". The data uses `ZUS`, with the title "ZUS + zaliczka PIT". A combined id is not modelled.
2. **Disabled reasons without spec text** (`outside_window`, `week_action_used`, `overdraft_active`, `payment_already_booked`, `not_playing`, `event_unresolved`) come with `text: null`. The narrative lane should add copy keys `card.disabled.<code>`. Reasons with spec text (budget_closed, bank_too_late, invoice_financed, invoice_paid, already_played) carry the Polish text from level1.json.
3. **Event choice labels**: only E1 (both choices) and E2 `accept` („Przyjmij”) have Polish labels in the spec. The others are `label: null`, so the narrative copy deck owns them.
4. **Invented titles** (no spec text, needed for the Cash Flow list): C2 inflow "Klient A, faktura INV-A1 ze skontem 2%", C5 repayment "Spłata pożyczki w 15 minut", C6 inflow "Faktoring ekspresowy, faktura INV-A1", E2 inflow "Klient C, nowe zlecenie", E3 "Narzędzie AI do grafiki". E3 counterparty is `O`. Please review.
5. **createPlan / savePlan split**: my reading of the contract is that `createPlan` returns the draft `Plan` and `savePlan` returns the prospective `GameState` (plan saved, Pilot earned), which the UI must persist before it shows success. Tell me if the UI lane expected something else.
6. **playerReturns** is in the event union, but no engine function emits it, because the engine cannot know about app sessions. The app or narrative builds `{ type: "playerReturns", week }` on resume.
7. **E5 `show_cost` competence**: the spec gives only "Koszt pieniądza 1". Data has own 1 / delegated 1.
8. **Bank rule order**: rules are evaluated first-match. For the bank: late (T4+), then not-needed (gap closed), then offer. Added a `bank.fallback` line id for unknown intents (not in spec §4.2). The narrative lane needs that copy key.
9. Non-demo seeds currently fall back to the demo deck. E-04 decides the seeded deck.
