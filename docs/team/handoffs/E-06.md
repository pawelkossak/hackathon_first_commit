# E-06: score — stars, competences, cost of money, avoided cost, overdraft interest

## Built
- `engine/score.ts` is now the score module:
  - `lapScore` (from E-03, unchanged rules). Cost of money = fixed card costs + overdraft interest. Avoided cost = 2 400 − cost. Stars come from the `level1.json` star rules. Level 2 unlocks with ≥ 1 earned star at lap end.
  - `awardCompetence(competences, id, level)` (new). It keeps the maximum, caps at `competenceMax` (3) and returns a new record. `cards.ts` (`applyCard`) and `events.ts` (`applyEventChoice`) now both use it instead of two inline copies.
  - `coreAfterValidation(core, cardId)` (new, internal). It raises the plan card's competence to milestone 3. A product card changes nothing, and stars and unlock are never touched. E-09 calls it from `advanceAccountClock` once the matcher returns `met`.
- `coreAfterPlanSave` (turn.ts) checked against ET-S01 and ET-S05 (the E-05 open point). It changes only Pilot `pending` → `earned` and keeps the unlock. Competences are unchanged by the save.
- **QA fix 1: the fraud stays hidden before the reveal.**
  - The forecast overlay context has a new internal flag, `groundTruth`. It is passed through the third parameter `ForecastMode` of `computeForecast` / `forecastTransactions`. That parameter is internal and not in the public `ForecastOptions`.
  - In every player-facing view (`forecast` with either `includeFutureEvents` value, `previewCard`, `getCfoHint`, `delegateBestCard`, the C4 estimate and `goodMove`), the E1 `reveal` and every effect after it stay hidden until 23 XII lies before the current week. That means from T6 on. This covers the L08 `eventId: "E1"` marker and the 8 I re-payment.
  - Only `settleWeek` (`resolveWeek`) uses `groundTruth: true`, so the real path still crashes on 8 I at E1 with a shortfall of 25 715 (ET-E02, ET-E03 unchanged).
  - `getCfoHint` ordering is unchanged.
- **QA fix 2: plans only from a winning lap.** `createPlan` (and so `savePlan`) throws `RuleError("plan_not_allowed")` in two cases:
  - the lap is not `completed`, meaning it is still running or it crashed;
  - the card was not played in the completed lap.

  No new error code.

## API changes
No signature changes, no new event types and no new error codes. Behaviour changes:
- `forecast(state)` (default) and `getCfoHint` no longer show the E1 fraud effects before T6.
- `createPlan` / `savePlan` throw `plan_not_allowed` mid-lap and after a crash. **UI:** offer "save as plan" only on a completed lap (G18 → G22). E-05 open point 1 ("a plan saved earlier must be saved again") is moot now: an earlier save is impossible.
- The internal (non-index) helpers `computeForecast` and `forecastTransactions` take an optional third parameter `ForecastMode`.
